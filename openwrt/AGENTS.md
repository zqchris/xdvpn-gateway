# XDVPN 开发入口

先读 README.md、docs/CONTINUATION.md，再按需读 docs/ACCEPTANCE.md 最新记录。历史记录是上下文，当前源码、配置与运行状态必须实时核验。

## 不可破坏的约定

- 优先低 CPU/内存，不为日志新增持续抓包进程、全量 DNS 日志或高频后台轮询。
- 不修改 OpenClash / Passwall 的配置、节点和订阅。只能维护 XDVPN 自有规则，允许只读引用相关域名规则。
- 公司私有 IP 清单位于仓库外；不纳入源码、测试、安装包或 Git。禁止提交密码、token、cookie、路由器配置备份和完整 `uci show network` 输出。
- 本地提交不代表授权公开发布。公开文档只保留脱敏案例；发布前仍需检查工作树、历史和安装包，不自行 push。
- 手动模式只接管填写的域名/IP；父域名包含子域名。第二种是公司预设＋手动补充：本机 IT 清单的 IP/域名与手动项合并；不使用服务器下发的全网路由。原 server 模式迁移为 company。
- Claude 保护在手动/公司预设模式默认开、允许用户关；全局忽略内置 Claude 保护。“其他黑名单”独立，在所有模式（含全局）优先排除。
- 保存分流规则立即热更新，不重连。账号、服务器、核心变更需要重连。不要为了测试擅自切全局或重启整个网络。
- 日志按具体子域名显示，同一域名固定 5 分钟窗口合并。真实隧道发送、规则推断、ECH 外层域名要明确区分，不能凭共享 IP 猜域名。
- LuCI 顶部不要用裸 header 元素，Argon 的全局 header::after 会遮挡界面。账户、分流、黑名单可折叠；核心切换端口 Hillstone 4433、OpenConnect 8443，端口可手改。

## 工作方式

- 先查看 git status，保留他人未提交的修改；按变更范围运行 README 中的验证。
- UI-only 修改可热更新 JS/CSS，避免安装包升级脚本触发 VPN 重连；具体做法及版本差异见交接文档。
- 更新交接文档中的状态与未验证边界。不要把本地模拟页面测试写成真实路由器浏览器验收。
- 本环境持久记忆按宿主提供的 cindy_memory 规则处理；新 agent 即使没有该工具，也可依靠本仓库文档接手。
- UI 发布需同时更新版本化入口/样式别名（当前 main_v073.js、style_v073.css）与菜单 action；别名复用规范源码，不能仅覆盖旧 URL。清理本机实际的 `/tmp/luci-indexcache.*.json`，再通过 HTTP 验证新资源，不能只比对磁盘文件。打包测试会校验版本与入口匹配。
