# 发布前隐私检查

本仓库只发布通用代码、合成测试数据和脱敏验证摘要。示例使用 example.com / example.org 等保留域名。
用户账号、证书信任配置、公司规则、部署拓扑、原始日志、截图、抓包和备份应存放在仓库外。
私有规则仍通过用户自行维护的文件导入；公开构建不读取该文件。

发布前检查当前目录、所有准备推送的分支/标签历史及安装包解包内容，不能只看最新一次 diff。
对照私人清单做精确匹配时，清单与扫描报告也留在仓库外；不要把真实敏感值写进公开的扫描测试或排除列表。
二进制应使用 `-trimpath` 重新构建，避免携带个人构建路径；不要复用旧截图、预览、诊断核心或安装包。

如果发现历史敏感信息，先在私人位置保留恢复备份，再清理发布分支及旧引用/对象。
本地清理不撤回已经公开的内容；若凭据曾被公开，应另外撤销或轮换。
隐私清理会改变提交 ID。不得从私人原始仓库、旧 bundle 或旧分支重新合入未经审查的提交。

提交 PR 时还需确认目标仓库、基线分支、许可证与贡献规范。不要为公开发布提交部署授权或真实设备信息。
