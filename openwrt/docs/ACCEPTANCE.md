# 验收摘要

此文档保留验证方法与边界，不公开部署地址、公司业务域名、IP 清单、账户或原始现场日志。

## 已验证

- x86_64、fw4、支持 nftset 的 dnsmasq 环境下，Hillstone 认证、隧道内 HTTPS、LAN 转发、主动断开与路由清理。
- 手动白名单与公司预设合并；父域名覆盖子域名；规则变更不重连现有 VPN。
- Anthropic 保护与自定义黑名单的优先级；普通非公司流量交还原网络。
- 在一个 OpenClash redir-host 环境中访问正常，更新前后其他代理配置保持一致。
- 修复公司网段覆盖 VPN 地址时，回程报文被重新标记进 VPN 的问题；真实 LAN 转发前后对照失败→成功。
- Hillstone 实际发送记录按完整域名显示，同一域名固定五分钟合并；IP-only 与 ECH 外层名称明确区分。
- 手机/桌面宽度的隔离页面布局、折叠、标签切换、端口切换与证书交互逻辑。

自动验证命令见 README。测试数据为合成示例；不得用生产凭据或真实公司规则建立回归夹具。

`tests/test-routing-netns.sh` 是 Linux/root 下的隔离网络回归测试，读取真实 priority 脚本的规则，
用临时 namespace 模拟 LAN、NAT 和 VPN 回程。原规则失败，修复后通过；退出时清理临时资源。
调用示例：`sh tests/test-routing-netns.sh package/luci-app-xdvpn/root/usr/libexec/xdvpn/priority`。

## 未完成或不能泛化的结论

- OpenConnect 的特定部署会话仍存在服务端主动断开及部分退出崩溃，未宣布修复。
- ARM64 只有构建验证，没有硬件验收。
- Passwall、Fake-IP、fw3/iptables、其他独立拦截基础链未全面验证。
- 全局模式与黑名单有离线覆盖，但没有以生产设备全局切换作为全面验收。
- 未提供真实登录态的 LuCI 浏览器端到端结论，也未完成长期满载吞吐、CPU 与重协商基准。
- DNS 分流受加密 DNS、缓存和共享地址影响；日志不是完整流量审计。

## 后续验收步骤

1. 记录固件、内核、CPU 架构、包管理器与防火墙/DNS 能力，私下保存可恢复备份。
2. 使用经授权的测试账号与测试业务，只导入明确的白名单。
3. 分别验证连接、访问、刷新规则、断连清理与重连。
4. 在空闲和持续流量下测量 CPU/RSS，不把单次快照当作性能上限。
5. 对照其他代理配置和普通网络访问，确认没有改变其配置。
